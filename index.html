Install

Load CSS, create a table, then add only the behaviors you need.

The starter path is intentionally short: install the package, import the stylesheet, pass rows and columns, and initialize.

Full install docs Remote demo
quick-start.js npm install dog-table 
import { DogTable } from "dog-table";
import "dog-table/css";

const table = new DogTable("#app", {
  data: [
    { id: 1, name: "Mochi", status: "ready" },
    { id: 2, name: "Pepper", status: "pending" },
  ],
  columns: [
    { key: "name", label: "Name" },
    { key: "status", label: "Status" },
  ],
});

table.init();
Start local

Use arrays first to confirm columns, rendering, search, sorting, and pagination before wiring remote data.

Switch to remote mode

Remote requests can respond to page, page size, sort, and search state with abortable loading.

Layer in app workflows

Add selection, persistence, export, formatting, editing, live refresh, and create flows as the screen grows.

Capabilities

Built for the table work that usually outgrows a snippet.

Data Local arrays and server-backed views

Use static rows for small screens, or move to remote mode when pagination and filtering belong on the server.

Interaction Search, sort, paginate, select, edit

Common controls are already wired into the table instance so product screens do not need a custom state machine.

Operations Export, persist, refresh, localize

App-level needs such as CSV export, saved preferences, live polling, and language bundles live beside the core table API.

Architecture

Dog Table splits behavior into focused layers.

The public API still starts with new DogTable(container, options), while the internals separate state, data processing, rendering, remote loading, events, and plugin bootstrapping.

State Page, page size, search, sorting, and guard constraints.
Data Filtering, sorting, slicing, grouping, and cache reuse.
Render Table structure, pagination UI, meta states, and row detail.
Plugins Persistence, selection, export, formatter, editor, live, create.
